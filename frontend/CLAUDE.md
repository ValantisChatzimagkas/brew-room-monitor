# Frontend rules (Next.js App Router)

Next 16 with `cacheComponents` on. APIs differ from older Next: check `node_modules/next/dist/docs/` before using an API you're unsure about.

## Data flow
- Browser never calls the backend directly. Server Components call it through `getApi()` in `src/lib/api/client.ts`.
- `client.ts` is `server-only` and holds `ADMIN_TOKEN`. Never import it from a `"use client"` file; never expose the token via `NEXT_PUBLIC_*`. It is the only file that reads `process.env`.
- Pass Client Components only the fields they render, not whole API objects (everything passed to them is sent to the browser).
- No mutating Server Actions until the frontend has auth (see root `CLAUDE.md`). After that, each action re-checks auth and validates its input itself.
- Types come from `src/lib/api/schema.d.ts` (generated by `make api-types`). Don't edit it or redefine API shapes by hand; re-export what you need from `client.ts`.
- Check `error` on every `api.GET/POST` result before using `data`.
- Uncached/live data: wrap the fetching component in `<Suspense>` with a fallback (build fails otherwise). Use `"use cache"` only for data that's truly static.

## Components
- Server Components by default. `"use client"` only on small interactive leaves (charts, toggles, forms with local state).
- Route files in `src/app/`; shared UI in `src/components/`; non-UI helpers in `src/lib/`. Create those folders when first needed.
- Styling: Tailwind utility classes only. No component library or CSS-in-JS until there's a clear need.
- Every route that fetches data has a sensible loading state and is covered by an `error.tsx`.

## Quality bar
- `pnpm lint` (zero warnings), `pnpm typecheck`, `pnpm build` all pass (`make check-frontend`).
- TypeScript strict; no `any`, no `as` casts to silence errors, no `@ts-ignore`.
- Format numbers with units in the UI, timestamps converted to local time at render.

## Tests
- No test runner yet, on purpose: types, lint and `next build` cover the current code.
- Keep logic out of components: pure helpers (formatting, aggregation) go in `src/lib/`. When the first one with real branching shows up, add Vitest for it and nothing else. No component snapshot tests.

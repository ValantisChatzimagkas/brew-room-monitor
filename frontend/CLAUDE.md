# Frontend rules (Next.js App Router)

Next 16 with `cacheComponents` on. APIs differ from older Next: check `node_modules/next/dist/docs/` before using an API you're unsure about.

## Data flow
- Browser never calls the backend directly. Server Components and Server Actions call it through `getApi()` in `src/lib/api/client.ts`.
- `getApi()` forwards the signed-in user's access token, read through `src/lib/auth0.ts` (Auth0 SDK, session in an encrypted httpOnly cookie). Both files are `server-only`: never import them from a `"use client"` file; never expose a token or provider secret via `NEXT_PUBLIC_*`. They are the only files that read `process.env`.
- No session, an expired token (Auth0; the local provider's sessions refresh instead) or a backend 401 redirects to sign-in inside `getApi()` (a 401 on a freshly issued session is a config error and throws instead); pages must not catch either. `src/proxy.ts` also redirects anonymous requests, but only `getApi()` is the authoritative check. The proxy lets Server Action POSTs (`POST` + `next-action` header) through without a session, so each action's `getApi()` is what sends it to sign-in.
- Scripted sign-in for checks and PR evidence: the local-provider recipe in `firmware/README.md` ("Getting a user token"); in a browser, type any username in the local provider's form.
- Pass Client Components only the fields they render, not whole API objects (everything passed to them is sent to the browser).
- Server Actions (pattern: `src/app/batches/[id]/actions.ts`; session and input rules in root `CLAUDE.md`): `actions.ts` next to the route; call `getApi()` before anything else; never catch `redirect`/`notFound`; `refresh()` after success, or `redirect()` when the action moves to another page; return field errors as state. A local time from a form is converted to UTC in the browser with `localInputToUtc` (`src/lib/time.ts`).
- A secret shown once (a device token) lives only in a Server Action's return state, never in a URL, cookie or log, and is cleared when the page is hidden (pattern: `useResetOnHide` in `src/components/device-token.tsx`).
- Types come from `src/lib/api/schema.d.ts` (generated by `make api-types`). Don't edit it or redefine API shapes by hand; re-export what you need from `client.ts`.
- Check `error` on every `api.*` result before using `data`.
- Uncached/live data: wrap the fetching component in `<Suspense>` with a fallback (build fails otherwise). Use `"use cache"` only for data that's truly static.

## Components
- Server Components by default. `"use client"` only on small interactive leaves (charts, toggles, forms with local state).
- Route files in `src/app/`; shared UI in `src/components/`; non-UI helpers in `src/lib/`. Create those folders when first needed.
- Every route that fetches data has a sensible loading state and is covered by an `error.tsx`. A missing or foreign id calls `notFound()` (never a custom "not found" message in the page), rendered by `src/app/not-found.tsx`.

## Design system (shadcn on Base UI)
- Before writing UI, in this order: reuse from `src/components/` → use `src/components/ui/` → `pnpm exec shadcn add <name>` (read `pnpm exec shadcn docs <name>` first) → only then compose a new component in `src/components/` from `ui/` pieces.
- `src/components/ui/` is vendored shadcn code. Change it through the CLI (`add <name> --diff` for upstream fixes), or add a `cva` variant once two call sites need it. Never edit it to style one page.
- Official `@shadcn` registry only; `.claude/settings.json` denies `shadcn add` with anything containing `/` (namespace, `owner/repo`, URL, path), so add by bare name: `add dialog`. If `add` installs npm packages, name them in your summary.
- Colors, radius and fonts come from tokens in `src/app/globals.css`; Tailwind's default palette is removed. A new color (e.g. an insight status) is a new semantic token there, with a dark value.
- Icons: `lucide-react`. Charts: shadcn `chart`. No other UI, icon or animation library, no CSS-in-JS.
- `eslint.config.mjs` enforces the above (unknown classes, arbitrary values, raw form elements, primitive and foreign imports). Fix the code; don't disable a rule inline.

## Quality bar
- `pnpm lint` (zero warnings), `pnpm typecheck`, `pnpm test`, `pnpm build` all pass (`make check-frontend`).
- TypeScript strict; no `any`, no `as` casts to silence errors, no `@ts-ignore`.
- Format numbers with units in the UI, timestamps converted to local time at render.

## Tests
- Vitest runs pure helpers in `src/lib/*.test.ts` (`pnpm test`, part of `make check-frontend`). No component or snapshot tests.
- Keep logic out of components: pure helpers (formatting, aggregation) go in `src/lib/`.
